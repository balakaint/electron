এই round-এ যা বদলালো (Phase 5A — generic data contract, একই vertical-slice test, নতুন কোনো UI/theme না):
① Entity model — flat ITEMS array-র বদলে এখন 4 layer: OUTCOMES (out_2026) → MILESTONES (ms_aug fixed, ms_sep live, প্রতিটার outcomeId) → WINS (win_w1/w2 fixed, win_w3 live, win_w4 fixed-0%, প্রতিটার milestoneId) → TASKS (৫টা Sep task-এর winId: 'win_w3')। কোথাও আর string-tag winFor নেই।
② Generic engine — winProgress(win) সরাসরি tasksForWin(win.id) filter করে % বের করে (fixed win হলে stored value), milestoneProgress(ms) সেই milestone-এর সব Win-এর average, outcomeProgress(out) সব Milestone-এর average — কোথাও 100+100+x+0-এর মতো literal formula নেই, সবটাই .filter()/.reduce() দিয়ে real relationship হাঁটা। v4-র exact numbers দিয়ে verify করা হয়েছে (initial 60/65/83% → complete হলে 100/75/88% — অবিকল মিলেছে, একটা Node stub-DOM script দিয়ে)।
③ WEEKS collection — currentWeek bare number ছিল, এখন currentWeekId একটা real WEEKS array-কে point করে (প্রতিটা week-এর নিজের days[], winId, elapsedDays) — shiftWeek(), day-strip, Week Win card সবই generic lookup দিয়ে render হয়, "week===3" if/else নেই।
④ Carry-forward — এখন target week-টাও WEEKS array থেকে generic ভাবে বের হয় (WEEKS[idx+1]), item-এর same id/object বজায় থাকে (আগের মতোই re-verify করা হয়েছে)।
⑤ Cascade toast — এখন কোনো win-এর জন্যই generic ভাবে কাজ করবে (win object + তার milestone/outcome দিয়ে message বানায়), শুধু "Week 3" hardcode করা নেই — যদিও এই স্লাইসে শুধু win_w3-ই live তাই এখনো এটাই দেখা যাবে।

Breadcrumb আগের মতোই সঠিক (Yearly=বছর, Monthly=বছর›মাস, Weekly=+সপ্তাহ, Daily=+দিন) — অপরিবর্তিত।

এখনো simplified/honest flag (deliberately not this phase's scope): "Schedule a specific date" এখনো carryForward('date')-এ "next week"-এর মতোই resolve হয় (real date→week derivation নেই) — এর জন্য future interaction contract কোড-এ comment হিসেবে লিখে রাখা আছে ({ planned_period, scheduled_date, status, parent_win })। Week 4-এর নিজস্ব কোনো live Win নেই (placeholder card দেখায়, কারণ tasks নেই) — fake data দেওয়ার বদলে সততার সাথে "not started" রাখা হয়েছে। Production-এ TASK/WIN/MILESTONE/OUTCOME-কে আলাদা collection হওয়া উচিত, এখানে এখনো একই TASKS array-তে type দিয়ে আলাদা করা (Top-3 / task / monthly-outcome) — এটাও এখনো prototype-level simplification, backend rewrite না। Theme স্পর্শ করিনি।
